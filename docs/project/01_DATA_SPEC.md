## 1. 数据集总体结构

本项目的早孕期数据包含两类用途不同、但可在病例层面关联的数据目录。

### 1.1 不带“已标心轴”的目录：分割数据

主要目录为：

``` text
正常胎儿/
阳性病例/
```

按队列组织，并包含分割任务相关文件：

``` text
img/
label_gold/
label_infer/
```

逻辑含义：

| 文件角色      | 含义                   | 正式用途                    |
|---------------|------------------------|-----------------------------|
| `img`         | 分割任务使用的超声图像 | 模型输入                    |
| `label_gold`  | 人工分割标签           | 分割监督GT                  |
| `label_infer` | 历史模型预测分割       | 历史预测/诊断，不作为人工GT |

### 1.2 带“已标心轴”的目录：人工心轴标注数据

主要目录名称包含：

``` text
正常胎儿-已标心轴/
阳性病例-心轴/
```

其中图像是医生进行人工心轴测量时使用的图像，TAR文件内含JSON及两条人工测量线。

**重要：** - 带“已标心轴”的图像与TAR属于人工心轴测量数据。 -
不带“已标心轴”的图像与Gold Mask属于分割数据。 -
两套数据通过病例标识建立病例级关联。 - `axis_img`
是Manifest/审计脚本中的逻辑角色名，不代表实际存在一个名为 `axis_img`
的独立文件夹。 - 不得把“已标心轴”目录图像默认当作nnUNetv2训练输入。

### 3.2 身份层级限制

正式唯一键：

``` text
uid = case_id + "|" + class + "|" + cohort
```

等价组合键：

``` text
(case_id, class, cohort)
```

现有合同明确： - `patient_id`当前来源为`case_id`； -
`patient_id`的患者身份含义尚未独立验证； -
`fold_group_id`也由`case_id`派生。

因此，当前只能称为 **case_id分组五折** 或
**病例级分组五折**。不得未经独立核实称为患者级五折。

## 5. 两批数据的关系

已确认： - 早孕期与中孕期数据来自完全独立的不同胎儿； -
没有同一胎儿跨孕周配对； - 不能构造样本级早孕—中孕配对监督； -
两批数据标签相似但不完全相同。

两套标签体系的语义**已由用户逐项确认**，登记于 `06_LABEL_SEMANTICS.md`：

- 早孕 Dataset501（7 类）：0 背景 / 1 胸椎 / 2 左侧肋骨 / 3 右侧肋骨 / 4 左侧心脏 / 5 右侧心脏 / 6 胸腔。
- 中孕 Dataset503（10 类）：0 背景 / 1 左心房 / 2 左心室 / 3 右心房 / 4 右心室 / 5 胸椎 / 6 胸腔 / 7 心内缘 / 8 未知区域（与心轴角测算无关） / 9 室间隔。

对应关系：早孕 ID1（胸椎）对应中孕 ID5（胸椎）；早孕 ID6（胸腔）与中孕 ID6（胸腔）概念一致但标注体系不同；其余无直接对应。中孕 ID8 保留为“未知区域”，不赋予解剖名称。

**相同数字不代表相同语义。** 任何迁移学习实现都必须依据 `06_LABEL_SEMANTICS.md` 的语义逐项确定监督范围，不能按相同数字 ID 直接共享监督；已确认语义也不等于可硬对齐。
